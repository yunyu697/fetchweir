# 品牌与图标

## 命名

- 产品名：**Fetchweir**（fetch + weir）。中文文档里首次出现时写「Fetchweir」，不缩写、不音译。
- 仓库 / 包名 / 产物名统一 `fetchweir`；版本 tag 带 `v` 前缀（`v1.0.0`）。
- 对外描述同类产品时使用「传统下载管理器」「同类工具」这类中性表述，不写具体品牌名。

## 图形语义

图标是**图形符号**，不是字母或缩写：

- **∏ 形闸墩**：三段式开口，顶部横梁 + 两侧立柱，对应 weir（堰/闸）的受控开口。
- **贯穿闸口的向下箭头**：取水向下流；箭头从闸口内部穿出，表示"流量被闸门约束地向下输送"。
- **下游水波**：两道渐弱波纹，交代水的去向；仅在中大尺寸出现。

整体读法是"闸门 + 下泄"，对应下载管理器"受控地把数据接到本地"的定位；不使用通用云朵、磁盘、
曲面箭头这些与同类工具高度雷同的元素。

## 颜色

| 角色 | 值 | 说明 |
| --- | --- | --- |
| 主色（渐变起） | `#7E8DFF` | 与应用强调色 `#6C8CFF` 同族，略偏亮 |
| 主色（渐变中） | `#5A6DE6` | 圆角方块主体 |
| 主色（渐变末） | `#3746BF` | 右下角压深，保证小尺寸下边缘不糊 |
| Glyph | `#FFFFFF` | 纯白，圆头笔画 |
| 单色稿（浅底） | `#1B2130` | 托盘/浅色系统栏 |

小尺寸稿不使用渐变，改为实色 `#586BE4`，避免 16px 下渐变抖动产生脏边。

## 小尺寸简化策略

| 尺寸 | 处理 |
| --- | --- |
| ≥32px | 标准稿：渐变 + 闸墩 + 箭头 + 两道水波 |
| 24px | 简化稿：去水波、去渐变、笔画加粗到画布宽度的约 11% |
| 20px | 同上，闸墩圆角半径减小，避免圆角吃掉笔画 |
| 16px | 同上，只保留闸墩与箭头两层结构；水波即使保留也会糊成灰雾，因此完全去掉 |

16px 的可辨识依据：实心圆角底 + 高对比白色双元素（外框开口 + 中心箭头），轮廓在 1px
缩放后仍有两个独立形状，不会退化为单个色块。

## 文件与产物

- 矢量源（可再生）：
  - `assets/icon/fetchweir.svg`：标准稿
  - `assets/icon/fetchweir-small.svg`：≤24px 简化稿
  - `assets/icon/fetchweir-mono-dark.svg`：白色单色，用于深色背景 / 深色托盘
  - `assets/icon/fetchweir-mono-light.svg`：深色单色，用于浅色背景 / 浅色托盘
- 生成脚本：`tools/Build-FwIcons.mjs`（无头 Edge 精确渲染 PNG，再合成 ico/icns；离屏运行）
- Windows：`src-tauri/icons/icon.ico`（16/20/24/32/48/64/128/256），安装包与卸载项沿用该 ico
- macOS：`src-tauri/icons/icon.icns`（含 32/64/128/256/512/1024）
- Linux：PNG 各档（512/256/128/64/48/32），打包器按尺寸取用
- 托盘：`tray-dark.png`（深色底用白 glyph）/ `tray-light.png`（浅色底用深 glyph）
- 浏览器扩展：`extension/icons/16.png`、`32.png`、`48.png`、`128.png`，与浮动条同一视觉语言
  （浮动条头部的圆角标记复用同一"闸门 + 箭头"轮廓）

生成命令：

```powershell
node tools/Build-FwIcons.mjs
```

脚本只写 `assets/icon/png/`、`src-tauri/icons/`、`extension/icons/`，不启动可见窗口。

未完成 / 受限项（如实记录）：

- **系统托盘实拍**已补齐：应用以普通权限、提权状态各常驻一次，均能从任务栏抓到图标；本机 100% 缩放（2880×1800）
  下图标默认落在「隐藏的图标」面板（Windows 11 对新托盘项的策略），实拍图同时给出通知区与面板两处。
  深色任务栏的实拍未取到（当前系统为浅色主题），深色底仍以 `tray-dark-light.png` 的资源渲染为准。
- **安装后资源管理器整屏**未做：只提取了快捷方式图标本身，没有对资源管理器/开始菜单整屏截图。
- **与同类工具的图标区分**只做了设计层面的对照（图形语义、配色、轮廓复杂度），未拿到对方图标源文件做像素级比对。

`windows-gnu` 链接器会报 `.rsrc merge failure: multiple non-default manifests`：rustc 自带的默认清单
（longPathAware + asInvoker）与 Tauri 生成的 Common-Controls 清单同为资源 id 1，链接器保留前者。
exe 内的清单已由上面的脚本确认存在但不含 Common-Controls v6；本应用不使用 Win32 通用控件对话框，
WebView2 与自绘托盘菜单不受影响。测试 / example 目标仍单独链接完整资源对象。
