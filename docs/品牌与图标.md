# 品牌与图标

## 命名

- 产品名：**Fetchweir**（fetch + weir）。中文文档里首次出现时写「Fetchweir」，不缩写、不音译。
- 仓库 / 包名 / 产物名统一 `fetchweir`；版本 tag 带 `v` 前缀（`v1.0.0`）。
- 对外描述同类产品时使用「传统下载管理器」「同类工具」这类中性表述，不写具体品牌名。

## 图形语义

图标是**图形符号**，不是字母或缩写：

- **三层入库板（vault）**：后两层低透明度、向上错位，表示排队中的分层存储；最前一层实色承载主色。
  整体轮廓是一个「把内容收进库里」的容器，而不是通用云朵、磁盘或曲面箭头。
- **贯穿板面的向下箭头**：内容被收进本地库，箭头是填充形状而非细线，保证小尺寸下仍是一个实心块。
- **亮暗两版**：同一轮廓，只交换底色与板色。浅底用深紫板，深底用浅紫板，避免在对应背景上失去边界。

程序图标（exe、安装包、任务栏、托盘、开始菜单/桌面快捷方式、卸载项）统一使用**亮色版**；
界面内的标题栏 logo 按当前生效的明暗主题取对应版本。

## 小尺寸简化策略

| 尺寸 | 处理 |
| --- | --- |
| ≥32px | 标准稿：三层板 + 细线箭头 + 底板横线 |
| 24 / 20 / 16px | 简化稿：两层板 + 实心填充箭头，去掉底板横线 |

16px 的可辨识依据：实心圆角底 + 高对比的两块独立形状（紫板 + 浅色箭头）。标准稿的箭头描边在
16px 下只有约 0.6px，会退化成灰雾，因此小尺寸改用填充路径，而不是简单缩放标准稿。

## 文件与产物

- 矢量源（可再生）：
  - `src/assets/brand-light.svg`：标准稿，亮底
  - `src/assets/brand-dark.svg`：标准稿，暗底
  - `src/assets/brand-light-small.svg`：≤24px 简化稿，亮底（程序图标小尺寸用）
  - `src/assets/brand-dark-small.svg`：≤24px 简化稿，暗底（界面暗色主题用）
- 生成脚本：`tools/Build-FwIcons.mjs`（无头 Edge 精确渲染 PNG，再合成 ico/icns；离屏运行）
- Windows：`src-tauri/icons/icon.ico`（16/20/24/32/48/64/128/256），安装包与卸载项沿用该 ico
- macOS：`src-tauri/icons/icon.icns`（含 32/64/128/256/512/1024）
- Linux：PNG 各档（512/256/128/64/48/32），打包器按尺寸取用
- 托盘：`app.default_window_icon()`，即亮色版程序图标；不再维护 `tray-dark.png` / `tray-light.png`
- 浏览器扩展：`extension/icons/16.png`、`32.png`、`48.png`、`128.png` 由同一脚本从亮色标准稿生成

旧的单色源（`fetchweir-mono-*.svg`）、旧标准稿（`fetchweir.svg` / `fetchweir-small.svg`）与
`tray-*.png` 已删除，仓库内只保留这一套新品牌资源。

生成命令：

```powershell
node tools/Build-FwIcons.mjs
```

脚本只写 `assets/icon/png/`、`src-tauri/icons/`、`extension/icons/`，不启动可见窗口。

## 颜色主题

颜色主题与明暗主题是**两条独立的轴**，可任意组合：

- 明暗：`data-theme="light|dark"`，用户偏好 `theme=light|dark|system`；`system` 通过
  `matchMedia('(prefers-color-scheme: light)')` 监听系统实际变化，变化时立即重绘。
- 颜色：`data-color="violet|azure|emerald|amber"`，默认 `violet`；选择器在设置页「外观」分组，
  与明暗分开一行，点击即时全局生效。

每套颜色主题都定义完整 token，而不是只改按钮：

| 组 | token |
| --- | --- |
| 背景 / 标题栏 | `--bg`、`--bg-2`、`--titlebar` |
| 表面层级 | `--panel`、`--panel-2`、`--panel-3` |
| 文字层级 | `--fg`、`--fg-2`、`--fg-3` |
| 边框 | `--line`、`--line-2` |
| 强调色 | `--accent`、`--accent-2`、`--accent-solid`、`--accent-solid-2`、`--accent-solid-hover`、`--accent-solid-active`、`--accent-fg` |
| 状态色 | `--ok`、`--warn`、`--err`、`--info` |
| 进度 / 图表 | `--track`、`--chart-1` ~ `--chart-4` |

实现要点：

- 默认紫罗兰直接写在 `html[data-theme]` 块里，保证 JS 未执行时首屏也有完整配色；
  其余三套用 `html[data-color="…"][data-theme="…"]` 覆盖整组 token（特异性更高）。
- 主按钮用 `--accent-solid` 系列（深色实底 + 白字），强调文字/图标用 `--accent`（深色主题下更亮），
  两者分开，避免"同一种紫既要当按钮底又要当链接字"导致其中一端对比度不够。
- 设置落盘字段为 `colorTheme`，与 `theme` 同存于 `%APPDATA%\Fetchweir\settings.json`；
  前端只更新对应字段，互不覆盖，重启后恢复。

对比度实测（WCAG 2.1，脚本逐套计算正文/面板、次级文字、强调文字、主按钮白字与状态徽标）：

| 组合 | 最低项 | 比值 |
| --- | --- | --- |
| violet / dark | 弱文字 / 面板 | 4.86 |
| violet / light | 弱文字 / 面板 | 4.82 |
| azure / dark | 弱文字 / 面板 | 5.08 |
| azure / light | 弱文字 / 面板 | 4.66 |
| emerald / dark | 弱文字 / 面板 | 5.24 |
| emerald / light | 弱文字 / 面板 | 4.78 |
| amber / dark | 主按钮白字 / 渐变末 | 5.02 |
| amber / light | 强调文字 / 背景 | 4.85 |

正文字号 13px，全部组合正文/背景 ≥ 7:1；主按钮白字最低 5.02:1；未出现暗色主题黑字黑底。

未完成 / 受限项（如实记录）：

- **截图口径**：8 张主题截图与 2 张设置页截图是同一前端、同一 WebView2 内核下的 demo 数据
  离屏渲染，不抢前台；真实应用另抓了 amber/light 与 violet/dark 两张（上表）。
  主题作用于全局 CSS token，两种口径渲染结果一致。
- **深色任务栏**未取到：当前系统为浅色主题，任务栏实拍只有浅色底；深色底以暗色版 SVG 与
  `theme-*-dark.png` 的界面实拍为准。
- **托盘位置**：本机 100% 缩放（2880×1800）下新托盘项默认落在「隐藏的图标」面板，
  因此实拍是展开后的面板，不是通知区常显位置。
- **与同类工具的图标区分**只做了设计层面的对照（图形语义、配色、轮廓复杂度），未做像素级比对。

`windows-gnu` 链接器会报 `.rsrc merge failure: multiple non-default manifests`：rustc 自带的默认清单
（longPathAware + asInvoker）与 Tauri 生成的 Common-Controls 清单同为资源 id 1，链接器保留前者。
exe 内的清单已由上面的脚本确认存在但不含 Common-Controls v6；本应用不使用 Win32 通用控件对话框，
WebView2 与自绘托盘菜单不受影响。测试 / example 目标仍单独链接完整资源对象。
