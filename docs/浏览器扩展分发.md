# 浏览器扩展分发（.crx 与替代方案）

## 结论先说

本地打包 `.crx` 可行，脚本已实测产出 CRX3 文件；**但普通用户不能靠双击安装**。
正式版 Chrome / Edge 对站外 `.crx` 的拦截是产品策略，不是打包问题：

- Chrome 稳定版只允许两种来源：应用商店，或企业策略（`ExtensionInstallForcelist` /
  `ExtensionSettings`）下发的托管设备；
- 直接拖入 / 双击站外 `.crx` 会报 `CRX_REQUIRED_PROOF_MISSING`（缺少商店证明）；
- Edge 同源策略，个人设备同样拦截；
- Firefox 不认 `.crx`，只认签名 `.xpi`。

因此本项目不把 `.crx` 当作面向普通用户的安装方式。

## 本地打包：怎么做、要求是什么

```powershell
# 只出商店上传用的 zip（不需要私钥）
./tools/Build-FwExtension.ps1

# 同时出 CRX3（需要与 manifest key 配对的 RSA 私钥）
./tools/Build-FwExtension.ps1 -FwKeyPath D:\keys\fetchweir-extension.pem
```

脚本行为：

1. 打 `fetchweir-extension-<version>.zip`（清单在根目录，供商店上传）；
2. 用私钥推导扩展 ID，与 `src-tauri/src/nm.rs` 的 `EXTENSION_ID`
   和 `extension/manifest.json` 的 `key` 比对，不一致直接终止；
3. 调用本机 Chrome/Edge 的 `--pack-extension` 生成 CRX3（签名与 ZIP 封装由浏览器完成）；
4. 校验文件头 `Cr24` 与版本号 3，输出 `.crx`。

硬性要求：

- 私钥必须是 **PKCS#8 PEM 的 RSA 密钥**；PKCS#1（旧 `openssl genrsa` 默认格式）会被浏览器拒绝：
  `openssl pkcs8 -topk8 -nocrypt -in old.pem -out new.pem`；
- 私钥必须与 `manifest.json` 里的 `key` 配对。仓库里只有公钥（`key`），私钥不入库；
  若换私钥，扩展 ID 会变，必须同步改 `manifest.json` 的 `key` 与 `nm.rs` 的
  `EXTENSION_ID`，并重新构建应用，否则 Native Messaging 的 `allowed_origins` 授权失败。

### 实测记录（本机）

| 项目 | 结果 |
| --- | --- |
| 生成商店 zip | 23.1 KB |
| 生成 CRX3 | 24,476 字节，magic `Cr24`，版本 3 |
| 扩展 ID 校验 | 私钥推导值与预期一致时通过；不一致时脚本终止 |
| PKCS#1 私钥 | 浏览器报 “must be a valid format (PKCS#8…)” 并拒绝 |
| 未提供私钥 | 只出 zip，并打印密钥生成/转换说明 |

## 分发组合与用户成本

| 方式 | 用户操作 | 是否需要审核 | 适用场景 | 成本 |
| --- | --- | --- | --- | --- |
| 解包目录加载（当前推荐） | 打开 `chrome://extensions` → 开发者模式 → 加载已解压 → 选 `extension/` | 否 | 内测、开发、企业内部分发 | 每台机器手动一次，重启浏览器仍在 |
| Edge 加载项商店 | 打开商店页 → 获取 | 是（提交审核） | 面向普通用户 | 一次性审核与后续版本更新 |
| Chrome 应用商店 | 同上 | 是（开发者账号 $5） | 面向普通用户 | 同上，审核更严 |
| Firefox 签名 XPI | 安装 `.xpi` 或 AMO 页 | AMO 未列出签名也需提交 | Firefox 用户 | 需适配 MV2/MV3 差异 |
| 企业策略 | 管理员用 `ExtensionSettings` / `ExtensionInstallForcelist` 下发 `.crx` 或更新源 | 否 | 托管设备、公司内网 | 需要域/管理端配置 |
| 自建更新源 | 首次仍需策略或开发者模式安装，之后自动更新 | 否 | 内测、企业 | 需要托管 `update_url` 与 CRX |

## 我们提供 .crx 时的适用条件

- 只服务 **内测**、**企业自建更新源**、**企业策略分发**；
- 文件名带版本号，不放在下载页的主按钮上；
- 设置页与复制出的安装步骤里明确写出「双击装不上、正式版会拦截」；
- 普通用户路径仍是：加载已解压目录，或走商店。

## 仍未验证

- 在真实企业策略环境下用 `.crx` 下发（需要托管设备或域环境）；
- Edge 加载项商店与 Chrome 应用商店的实际提交流程与审核结果；
- Firefox 版本：当前 manifest 为 Chromium MV3，Firefox 需要单独适配后再签名打包。
