# Fetchweir 1.0.8 发布说明

发布日期：2026-11-09

## 本版变更

### 浏览器扩展悬浮条跟随应用颜色主题

此前网页里的悬浮条使用扩展自带的固定蓝黑/白配色，应用里换成海蓝、森绿或暖砂后，
网页内仍是另一套观感。本版把悬浮条纳入同一套颜色主题：

- 悬浮条不再有自维护的调色板，颜色只来自 `src/styles.css` 的 token。扩展内的固定
  `#6C8CFF` 蓝、`rgba(13,15,20,.86)` 面板底与 `prefers-color-scheme` 分支已全部移除；
  工具栏徽标底色也改为跟随应用的强调色，不再是固定蓝。
- 亮/暗 × 紫罗兰、海蓝、森绿、暖砂共 8 种组合全部跟随，面板、行、按钮、图标徽标、
  标题与副信息逐项对齐应用 token。
- 首帧先等主题就绪再绘制；应用从未下发主题时退回中性样式（`#1E1E23` 底 / `#F2F2F4` 字），
  不会先闪一套颜色再变。

### 下发链路与延迟

1. 应用切换明暗或颜色主题后，前端读取 `document.documentElement` 的计算样式，
   把 `--panel`、`--panel-2`、`--line`、`--fg`、`--fg-2`、`--accent-solid` 等 token
   经 `set_bar_theme` 交给 Rust；
2. Rust 校验后原子写入 `%APPDATA%\Fetchweir\bar-theme.json`；
3. Native Messaging 宿主每 700ms 检查该文件，变化时向扩展主动推送 `type=theme`；
   `hello` / `ping` 应答也携带最新主题，扩展冷启动首帧即可用。

应用内换主题后，**已打开的页面无需刷新**，通常约 1 秒完成换色（前端 60ms 合并 +
宿主 ≤700ms 轮询 + 广播）。实测切换前后页面 `performance.timeOrigin`、导航次数与 URL 均不变。

### 对比度实测

按 WCAG 相对亮度，对真实渲染的悬浮条计算 8 组组合，结果取自浏览器计算样式而非设计值：

| 元素 | 最低对比度 | 要求 |
| --- | --- | --- |
| 标题 | 15.18 | ≥ 4.5 |
| 站点名 / 底部提示 | 6.86 | ≥ 4.5 |
| 资源名 | 14.04 | ≥ 4.5 |
| 资源副信息 | 6.44 | ≥ 4.5 |
| 主按钮 / 类型徽标 | 6.50 | ≥ 4.5 |
| 禁用按钮（WCAG 豁免，仅要求可读） | 5.82 | ≥ 3.0 |

没有出现浅底浅字。悬浮条内没有进度条，下载进度只存在于应用窗口。

### 验证范围

- 真实浏览器（Edge headless + 已加载扩展）实拍亮/暗 × 四套配色，逐项核对悬浮条
  计算样式与 token 一致；截图与逐项结果在 `docs/ui-shots/extension-bar-theme-*`。
- 应用侧通过 WebView2 远程调试真实点击主题按钮，不是直接改配置文件。
- 三档判定回归：A/B/C 三档均重跑，C 档仍只出徽标不出条；无媒体页面不出现悬浮条。
- 自动化复跑：`node tools/Test-FwBarTheme.mjs <fetchweir.exe>`。

## 已知限制

- **应用未运行时，扩展无法感知新的主题变化**，悬浮条沿用最后一次落盘的主题；
  应用启动后会恢复实时跟随。
- **Firefox 版未联调 Native Messaging 往返。** Firefox 构建复用同一份
  `content.js` / `background.js`，代码路径一致，但宿主注册与实时推送未在 Firefox 实测。
- 内容类型缩略图渐变与窗口关闭按钮的红色是固定装饰色，不随颜色主题走。
- **安装包未做代码签名。** 新用户首次运行会触发 Windows SmartScreen，需点「更多信息」→「仍要运行」；
  请只从本仓库 Releases 页下载。
- **浏览器扩展需要手动加载**，发布包不包含已安装的扩展；需在 `chrome://extensions`
  开启开发者模式，选择安装目录下的 `extension` 文件夹。
- **CI 只构建 Windows x64。** 本版没有 dmg/deb/AppImage 产物。
- 不做 DRM / 付费墙 / 访问控制绕过；受保护流在解析阶段直接拒绝。

## 升级方式

- 1.0.7 → 1.0.8：覆盖安装即可，设置、颜色主题与任务记录都会保留。
- 1.0.6 及更早版本：覆盖安装即可；1.0.4 及更早版本升级后任务列表从空开始。
- 本版 Release 按流程生成 `latest.json` 与 `latest.json.sig`，应用内「检查更新」可收到 1.0.8；
  若 Release 缺少这两个文件，则只能手动下载安装包。
