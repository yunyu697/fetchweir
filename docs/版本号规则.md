# 版本号规则

## 单一来源

版本号只有一个写入手：仓库根目录的 `version.json`：

```json
{ "version": "1.0.0-alpha1" }
```

其余全部由它派生，不允许在别处手写版本字符串：

| 使用方 | 取值方式 |
| --- | --- |
| Rust 编译期常量 `FETCHWEIR_VERSION` | `src-tauri/build.rs` 读 `version.json` 注入 |
| 界面标题栏 / 关于 / 状态栏 | 启动时由 `app_info` 返回同一个常量 |
| Tauri 打包版本 | `tauri.conf.json` 的 `version` 指向 `../version.json` |
| 安装包 / 产物名 | Tauri bundle 取 `productName` + 版本；本地 `-FwTask release` 落到 `dist/` |
| `Cargo.toml` | 固定 `0.0.0` 占位，不参与展示 |

## 格式与取值范围

```
<major>.<minor>.<patch>[-alpha<N>]
```

- `major`：不设上限。
- `minor`、`patch`：**0–10**，不允许出现 11；越界时 `build.rs` 直接让构建失败。
- `alpha<N>`：预发布编号，不设上限。
- 起始 `1.0.0`；第一次对外推送使用 `1.0.0-alpha1`。

## 进位规则

| 操作 | 结果 |
| --- | --- |
| patch + 1，且结果 ≤ 10 | `major.minor.(patch+1)` |
| patch = 10，再升 patch | `major.(minor+1).0` |
| minor = 10，再升 minor | `(major+1).0.0` |
| alpha + 1 | 数字位不变，`alpha(N+1)` |
| alpha 转正式（release） | 去掉 `-alphaN`，数字位不变（`1.0.0-alpha2` → `1.0.0`） |

## Git tag

- tag 一律带 `v` 前缀：`v1.0.0-alpha1`。
- **tag 只是版本标记**：不触发打包、不创建 Release、不上传产物；安装包由本地
  `tools/Build-Fw.ps1 -FwTask release` 生成。
- `tools/Test-FwVersion.ps1 -FwTag <tag>` 校验 tag 必须以 `v` 开头、去掉前缀后与 `version.json` 完全一致；
  CI 在 tag 推送时只跑这一步。
- 打 tag 前先 `Next-FwVersion.ps1 -FwApply` 把 `version.json` 改成同一个值，否则标记与源码版本对不上。
- 是否打 tag、是否重跑旧 tag 由仓库所有者决定；本仓库当前口径是「只同步代码、暂不发版」时不要补 tag。
