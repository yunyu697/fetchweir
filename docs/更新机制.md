# 更新机制（v1.0.4 起）

## 为什么改

源码仓库是私有的。客户端不带令牌访问 `https://api.github.com/repos/{owner}/{repo}/releases`
会直接 404，旧实现把「取不到」和「没有新版本」混在一起，用户端表现为
「已是最新版本仍提示有更新」或「更新源不可访问」。

另外旧实现把 GitHub 访问令牌存在本地设置里，等于把一个长期有效、
能读私有仓库的凭据放进每个用户的机器，不能接受。

## 采用的方案：公开「发布产物」仓库

```
私有源码仓库 (yunyu697/fetchweir)
        │  CI 构建（tag 触发）
        ▼
私有 Release：安装包（内部存档）
        │  publish-public job（需 FW_RELEASES_PAT）
        ▼
公开仓库 (yunyu697/fetchweir-releases)
        └─ Release: 安装包 + latest.json + latest.json.sig
                    │
                    ▼
        客户端只读 https://github.com/<repo>/releases/latest/download/latest.json
        用内置 Ed25519 公钥验签 → 选平台资产 → 下载 → 校验 SHA256 → 安装
```

- 公开仓库只放产物与清单，不放源码；没有令牌、没有私有 API。
- 客户端 `DEFAULT_REPO` 已改为 `yunyu697/fetchweir-releases`，设置页仍可改成自建源。
- 访问令牌输入框与 `updateToken` 字段已删除，导出配置里也不再出现。

### latest.json

```json
{
  "version": "1.0.4",
  "published_at": "2026-11-07T10:36:04Z",
  "notes": "更新说明",
  "min_system": {
    "windows": "Windows 10 1809 及以上",
    "macos": "macOS 11 及以上",
    "linux": "glibc 2.31 及以上"
  },
  "assets": [
    {
      "platform": "windows",
      "arch": "x86_64",
      "name": "Fetchweir_1.0.4_x64-setup.exe",
      "url": "https://github.com/yunyu697/fetchweir-releases/releases/download/v1.0.4/Fetchweir_1.0.4_x64-setup.exe",
      "size": 12345678,
      "sha256": "…"
    }
  ]
}
```

`latest.json.sig` 是 `latest.json` 原始字节的 Ed25519 签名（base64）。
两者都由 `tools/Publish-FwRelease.ps1` 生成。

### 客户端校验顺序

1. 取 `latest.json` 与 `latest.json.sig`。
2. 用内置公钥验签：失败 → **直接中止**，不回退、不安装。
3. 版本按语义化规则比较（含预发布优先级，见 `src-tauri/src/update.rs` 单测）。
4. 预发布版本只在当前版本本身是预发布时才会被推荐。
5. 下载完成后校验 SHA256；不匹配 → 删除临时文件并拒绝安装。
6. 旧更新源没有清单时，回退到 Release 列表，但状态里标 `verified=false`，
   界面显示「未校验来源」，且没有 SHA256 可校验。

## 四种方案取舍

| 方案 | 做法 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- | --- |
| 公开发布仓库（已采用） | 私有源码 + 公开产物仓库 + 签名清单 | 无凭据、可镜像、可离线校验、实现简单 | 产物公开可见 | 采用 |
| 自建更新源 | 自己的 HTTPS 放 latest.json + 安装包 | 完全可控、可灰度 | 需要域名/服务器/证书与运维 | 支持（设置里改仓库或后续加源地址），当前未部署 |
| 代理层 | 自己的服务端持有令牌，客户端访问代理 | 不暴露令牌 | 代理本身要运维，且仍是中心化信任点 | 不作为默认，可用自建源替代 |
| 内置令牌 | 客户端带 PAT 读私有仓库 | 改动最小 | 令牌可被提取，等于把私有仓库读权限发给所有用户；PAT 轮换要重新发版 | **排除** |

排除内置令牌的理由：桌面端无法安全保存共享密钥（本地文件、内存、抓包都能拿到），
一旦泄露影响的是整个仓库；而且每次轮换都要发新版客户端，实际不可维护。

## 镜像

- 镜像只对 `https://github.com/...` 的资产链接有效（前缀转发）。
- 清单资产地址不是 github.com 时（自建源），下拉框自动禁用并显示
  「当前更新源为自建地址，镜像加速不可用」，不会留一个点了没反应的选项。
- 私有仓库场景下 GitHub 加速站本来就无效；现在的公开仓库模式下才成立。

## 用户端如何收到更新

1. 设置 → 通用 → 检查更新（或启动后的手动检查）。
2. 有新版时显示版本号、发布说明、最低系统要求与「签名已校验」标记。
3. 「更新」= 下载 → 校验 → 安装 → 重启；「仅下载」= 落到系统下载目录。

## CI 需要的凭据

| Secret | 用途 | 状态 |
| --- | --- | --- |
| `FW_RELEASES_PAT` | 对 `yunyu697/fetchweir-releases` 有 `contents: write` 的 PAT | **待用户提供**；未配置时 `publish-public` 直接跳过 |
| `FW_SIGNING_KEY` | 与客户端内置公钥配对的 Ed25519 私钥（PKCS#8 PEM） | **待用户提供**；未配置时脚本拒绝发布未签名清单 |

首次配置步骤：

```powershell
# 1. 生成密钥对（本机执行，输出公钥并把私钥写进 .secrets/update-signing.pem）
node tools/New-FwSigningKey.mjs
# 2. 公钥写入 src-tauri/src/update.rs 的 RELEASE_PUBKEY_B64；公钥被编译进二进制，
#    替换后必须重新构建发版才生效
# 3. 私钥内容存进仓库 secret FW_SIGNING_KEY；PAT 存进 FW_RELEASES_PAT
```

> 私钥种子只保存在本机 `.secrets/update-signing.pem`，该目录已被 `.gitignore` 覆盖，
> 不要复制进 Issue、日志、文档或提交。公钥可以公开。

## 已验证 / 未验证

已验证（本机）：

- `tools/Publish-FwRelease.ps1 -FwDryRun` 生成清单，4 个假产物全部带 SHA256；
- 用 Node 的 `crypto.verify` 独立验签：PASS；逐个比对 SHA256：全部一致；
- 篡改清单任一字节后验签失败（Rust 单测 `builtin_pubkey_verifies_reference_manifest`）；
- 自建源地址时镜像列表降级为单一直连（Rust 单测）。

未验证：

- `publish-public` job 的真实运行（GitHub Actions 账户当前因付款/额度问题无法启动，
  见 `docs/release-notes-v1.0.4.md`）；
- 公开仓库创建、PAT 权限、真实 Release 资产下载链路。
