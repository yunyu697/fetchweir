# 1.0.10

本版只做一件事：让界面不再声称做不到的事。新增的三项都是把已有后端能力接到界面上，
另外两项后端确实没有能力，界面改为明确写「暂不支持」。

## 已实现未验证：启动后最小化到托盘

设置 → 常规新增「启动后最小化到托盘」。开启并重启后，主窗口不再弹出，应用只驻留托盘；
点击托盘图标仍可唤回窗口。设置随其他偏好一起保存，标注「下次启动生效」。

**未验证**：还没有在真实安装版上做「开启 → 重启进程 → 窗口不出现 → 托盘唤回」的实测截图。
功能状态清单里仍记为「已实现未验证」。

## 已实现未验证：输出容器（仅纯视频流合并）

视频页的容器选择器已接到下载参数：

- 选择「自动（跟随源）」保持原行为；
- 选择 MP4 / MKV 时，纯视频流合并会用 ffmpeg 输出为所选容器（`--merge-output-format`）。

边界写清楚：直链整文件与纯音频**不做转封装**，容器跟随源格式，选择器在这些档位保持禁用并说明原因。
MP4 与所选编码不兼容时，解析器可能改为 MKV 或报错。

**未验证**：尚未实跑一次 MP4 / MKV 合并并用 ffprobe 核对实际容器。

## 已实现未验证：进度条分段刻度

设置 → 外观新增「进度条分段刻度」。开启后，任务列表的进度条会按后端下发的真实分段规划
画出边界线，而不是按固定间距假装分段。

**未验证**：还没有开启开关后的截图或采样记录。

## 暂不支持：全局连接上限

下载引擎目前只有自动全局预算：额度为各活跃任务设定分段数之和，多任务时按总吞吐统一降档/恢复。
没有用户可设的全局上限字段与命令，因此界面上的滑杆标为「暂不支持」，并写明自动预算的实际行为。
不再保留「后端只提供单任务上限」这类不准确说明。

## 暂不支持：自动嗅探当前标签页

浏览器扩展当前始终捕获可下载资源，没有可下发的关闭开关（`autoCapture` 键只读不用）。
界面标为「暂不支持」，并写明无法在应用内关闭或按标签页切换，不再留一个看起来能用的开关。

## 文案更正：同时下载任务数

原说明写「超出部分进入排队」「按全局队列顺序执行」，与事实不符。当前每个任务启动后直接并发，
没有任务级并发限制，也没有全局队列。界面已改为「当前所有任务直接并发，暂不支持限制同时下载数」。

## 已知限制（与功能状态清单一致）

- 只发布 Windows x64；macOS 缺 arm64 ffmpeg sidecar 与公证流程，Linux 安装路径未实测。
- 安装包未做 Authenticode 代码签名，新用户首次运行可能触发 SmartScreen。
- YouTube 登录态的成功解析路径仍未验证；Cookie 来源的失败引导与回退已实测。
- 应用内「安装并重启」的真机覆盖安装仍未验证。

## 实测情况（如实）

- `cargo test`：43 项通过（含输出容器白名单单测）。
- 离屏 UI 启动检查：0 控制台错误、8 行任务、无横向溢出。
- 上述三项接线尚未做真机验证，状态保持「已实现未验证」，没有写成「已跑通」。

## 升级方式

应用内「检查更新」或从 Release 下载安装包覆盖安装（普通版 / 全用户版二选一）。
设置、任务记录与主题保持不变。

## 发布后补验（2026-11-14，正文保持发布时原样）

以上三处「未验证」已在本机真实安装版上补齐，已发布文案不改写：

- 启动后最小化到托盘：真实启动主窗口不显示、托盘右键可唤回，两次重启后设置仍生效；
- 输出容器：Bilibili 1080p 纯视频流选 MKV 下载，ffprobe `format_name=matroska,webm`；直链与纯音频档位保持禁用；
- 进度条分段刻度：真实 4 段下载中刻度与 `segments` 的 `end/total` 逐项一致；
- 应用内「安装并重启」：1.0.9 → 1.0.10 覆盖安装，版本、设置与任务记录保留。

证据见 `docs/evidence/v1.0.10-start-tray/`、`v1.0.10-container/`、`v1.0.10-ticks/`、`v1.0.10-upgrade/`。
