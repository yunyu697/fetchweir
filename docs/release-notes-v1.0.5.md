# Fetchweir 1.0.5 发布说明

发布日期：2026-11-08

## 本版变更

### 视频下载：分离流站点可用了

Bilibili 这类只提供「视频流 + 音频流分开」的站点，此前纯视频档整行禁用、后端直接拒绝。
1.0.5 起：

- 纯视频档走解析器 `{format_id}+bestaudio/best`，由随包 ffmpeg 合并音轨；
- 纯音频档交解析器直下；直链整文件仍走自家分段引擎；
- 估算体积把自动匹配的音轨算进去（Bilibili 1080p：视频 66.6 MB + 音轨 ≈ 71.7 MB）。

实测（2026-11-08，离屏 + ffprobe）：

| 用例 | 界面选择 | 成品 | ffprobe 实读 |
| --- | --- | --- | --- |
| Bilibili 1080p | `30080`（1920×1080 H.264 25fps 2629 kbps 66.6 MB） | 75,234,071 字节 | h264 High 1920×1080 25fps 2,627,607 bps + AAC 48 kHz 双声道 201,984 bps |
| Bilibili 纯音频 | `30216`（46 kbps） | 1,167,163 字节 | 仅 AAC 46,615 bps，无视频轨 |
| archive.org 直链 | `1`（640×360） | 61,878,609 字节 | h264 Constrained Baseline 640×360 24fps 697,070 bps + AAC 128 kbps |

格式矩阵与 `yt-dlp -J` 逐档比对：Bilibili 15 档（12 视频 + 3 音频）分辨率/编码/码率/体积/协议全部一致，
没有「显示可选但实际下不了」的档位。

同时修复：中文标题下成品路径为空（本地代码页输出被按 UTF-8 解码失败）、
非 ASCII 路径被解析器打印成 8.3 短路径。

### 批量嗅探下载

一次多选多个嗅探资源批量入队，11 个任务同时下载：

- 任务数没有上限；全局连接预算是各任务设定之和（11 × 8 = 88 条），起跑即满额；
- 429/503 在 10 秒内命中 3 次全局砍半，实测 1123 ms 从 88 降到 44；
- 单个任务扛过 2 次 503、3 次 429 后完成；404 任务进入「需处理」，不影响其他任务；
- 10 个成品 sha256 全部与源一致。

修复：入队瞬间（首个 3 秒 tick 之前）收到的 429/503 会被丢弃，导致「服务端记到限流、预算却没动」。

### 发布流程

- 推送 tag 后 CI 构建两个安装范围包（当前用户 / 所有用户）并上传 Release，
  上传前校验两包字节不同、内嵌清单分别是 `asInvoker` 与 `requireAdministrator`；
- 仓库配置 `FW_SIGNING_KEY` 时自动生成并签名 `latest.json`；
  未配置时流水线显式标注「未签名发布」，不会静默跳过。

## 已知限制

- **CI 只构建 Windows x64。** macOS 缺 arm64 版 ffmpeg sidecar，且没有公证/签名流程；
  Linux 的 deb/AppImage 安装路径未实测。本版没有 dmg/deb/AppImage 产物。
- **探测请求上的 429/503 不触发全局降档**：只有分段请求被限流才会降档；
  站点只对首个请求限流、分段正常时，并发预算不会变化。
- 更新检查仍是「验签 + SHA256」的清单机制，镜像加速下载未逐一实测。
- 不做 DRM / 付费墙 / 访问控制绕过；受保护流在解析阶段直接拒绝。
- YouTube（bot 校验）、Vimeo（HTTP 403）本轮不可用，原因与操作见 `docs/视频站点实测.md`。

## 升级方式

- 1.0.4 及之后的版本：安装包覆盖安装即可，配置与任务目录不受影响（任务不落盘，重启后清空）。
- 若本版 Release 未附带 `latest.json`，应用内「检查更新」不会发现 1.0.5，需要手动下载安装包。
