# Fetchweir 1.0.6 发布说明

发布日期：2026-11-08

## 本版变更

### 任务列表与进度落盘，重启后可续传

此前关闭或崩溃后任务列表清空，未下完的文件只能手动处理。1.0.6 起：

- 任务列表、分片进度、已完成记录写入 `%APPDATA%\Fetchweir\tasks.json`，
  采用临时文件 + 同名替换的原子写法，写一半断电不会留下半截清单；
- 上次退出时仍在下载/排队的任务，重启后恢复为「暂停」而不是「失败」，点继续即按原分片续传；
- 已完成记录在重启后保留；若成品文件被用户移走或删除，该条目标为失败并说明原因；
- 进度类变更按 1Hz 合并写盘，增删任务、暂停/继续、完成/失败等结构变更与退出时立即写，
  不会因为每个数据块都落盘而拖慢界面。

实测（2026-11-08，离屏 + CDP 驱动，12 MiB 本地限速 1.2 MB/s）：

| 环节 | 结果 |
| --- | --- |
| 下载到 58.6% 时强杀进程 | `tasks.json` 已记录 `state=active`、`done=6,750,208`、4 个分片进度 |
| 落盘频率 | 3 秒窗口内 `tasks.json` 只写 4 次 |
| 重启 | 任务恢复为 `paused`，`done` 与强杀前一致，未标失败 |
| 续传 | 4.0 秒完成，状态 `completed`，`.part` 已清理 |
| 成品校验 | 12,582,912 字节，SHA256 `e3b046bf…481521f` 与源一致 |
| 再次重启 | 已完成记录仍在，`done=12,582,912` |

### 卸载残留修复

旧版卸载后可能留下浏览器 Native Messaging 宿主注册与 `WebView2Loader.dll`，导致程序目录删不掉。
本版安装器在卸载阶段清理 Chrome/Chromium/Edge/Brave/Vivaldi/Mozilla 六处宿主注册与
`%APPDATA%\Fetchweir\nm` 下的清单，再删除程序目录；升级安装（`$UpdateMode = 1`）不受影响。

## 已知限制

- **安装包未做代码签名。** 项目暂无代码签名证书，`Fetchweir_*_x64-setup.exe` 以未签名形式发布。
  新用户首次运行会触发 Windows SmartScreen，需点「更多信息」→「仍要运行」；
  请只从本仓库 Releases 页下载。
- **浏览器扩展需要手动加载。** 发布包不包含已安装的扩展，也没有一键安装入口；
  需解压扩展目录后，在 `chrome://extensions` 开启开发者模式，选择「加载已解压的扩展程序」。
  Native Messaging 宿主清单由应用自动注册，无需手动改注册表。
- 任务持久化只记录下载地址、分片进度与路径；浏览器接管时附带的 Referer/Cookie 不落盘，
  重启后续传若站点需要这些请求头，可能返回 403，需要重新从浏览器发起。
- 删除应用数据目录（`%APPDATA%\Fetchweir`）会同时清空任务记录与设置。
- **CI 只构建 Windows x64。** macOS 缺 arm64 版 ffmpeg sidecar，且没有公证/签名流程；
  Linux 的 deb/AppImage 安装路径未实测。本版没有 dmg/deb/AppImage 产物。
- 不做 DRM / 付费墙 / 访问控制绕过；受保护流在解析阶段直接拒绝。

## 升级方式

- 1.0.5 及更早版本：安装包覆盖安装即可。`%APPDATA%\Fetchweir` 下的设置不会被动；
  1.0.4 及更早版本此前没有任务落盘，升级后任务列表从空开始。
- 1.0.6 及之后版本：覆盖安装后任务列表、分片进度与已完成记录都保留，未完成任务继续即续传。
- 若本版 Release 未附带 `latest.json`，应用内「检查更新」不会发现 1.0.6，需要手动下载安装包。
