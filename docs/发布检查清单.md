# 发布检查清单

发版前逐项打勾；任何一项不成立就停下，不要靠"应该没问题"放过。

## 1. 发布口径

- [ ] 本版发布方式：**本地构建 → 手动创建 Release**。CI 在 tag 上只校验 `version.json`，
      不打包、不上传；不要为了省事把打包/上传逻辑加回 workflow。
- [ ] 仓库所有者要求"只同步代码"时：只 commit + push `main`，不打 tag、不动已推送的 tag。
- [ ] 平台范围如实记录：本轮只构建 Windows x64 时，Release 里就只有两个 exe，
      发布说明必须写明 macOS/Linux 未本地构建，不能用模糊措辞暗示三平台都可用。

## 2. 版本号

- [ ] `version.json` 是本次要发布的版本，且格式合法：
      `pwsh tools/Test-FwVersion.ps1 -FwTag vX.Y.Z` 通过（不打 tag 时去掉 `-FwTag`）。
- [ ] 需要打 tag 时，tag 名与 `version.json` 完全一致（`vX.Y.Z`）。

## 3. 本地出包

- [ ] 一条命令出两个安装范围：

      ```powershell
      pwsh -NoProfile -File tools/Build-Fw.ps1 -FwTask release
      ```

- [ ] 出包前确认两个 sidecar 都在 `src-tauri/binaries/`（不入库，需先同步一次）：

      ```powershell
      ./tools/Sync-FwYtdlp.ps1
      ./tools/Sync-FwFfmpeg.ps1
      ```

      两个脚本默认按 msvc 三平台命名；本机是 MinGW（gnu）工具链时要显式给 triple，
      例如 `-FwTriple x86_64-pc-windows-gnu`，文件名必须与构建用的 triple 一致。

      缺 ffmpeg 时构建会直接报 `resource path binaries\ffmpeg-<triple>.exe doesn't exist`；
      装上后「纯视频流 + 最佳音轨」的合并才能用（设置页会显示「就绪」）。
- [ ] 终端打印的版本号与 `version.json` 一致，`dist/` 下有两个文件：
      `Fetchweir_X.Y.Z_x64-setup.exe`（currentUser）、
      `Fetchweir_X.Y.Z_x64-setup-allusers.exe`（perMachine）。
- [ ] 记录两个包的字节数与 SHA256（命令已打印），分发时一并给出。
- [ ] 抽查内嵌 `fetchweir.exe` 的 ProductVersion/FileVersion 等于本次版本。

## 4. 清单与签名（每次手动发版）

- [ ] 生成清单：`node tools/New-FwManifest.mjs`（只收录 `dist/` 里真实存在的安装包，
      没构建的平台不会出现在清单里）。
- [ ] 签名私钥仍是 `.secrets/update-signing.pem`，**没有重新生成**。
- [ ] 私钥与 `src-tauri/src/update.rs` 的 `RELEASE_PUBKEY_B64` 配对：
      把私钥内容放进 `FW_SIGNING_KEY` 后跑 `node tools/Sign-FwManifest.mjs --in dist/latest.json`，
      不配对会以退出码 3 拒绝。
- [ ] 清单里的 `url` / `size` / `sha256` 与实际分发的安装包一致。
- [ ] 本地验签通过；改动清单任意一个字节后验签失败。
- [ ] 本次没有修改 `RELEASE_PUBKEY_B64`。若改了，视为换钥：必须先发布带新公钥的版本。

## 5. 创建 Release 与说明

- [ ] tag 打在本次发布对应的提交上（`vX.Y.Z`），推送后只触发 CI 版本校验。
- [ ] 用 `gh release create vX.Y.Z --title "Fetchweir vX.Y.Z" --notes-file docs/release-notes-vX.Y.Z.md`
      上传两个 exe 以及 `dist/latest.json`、`dist/latest.json.sig`。
- [ ] `gh release view vX.Y.Z` 核对资产名、字节数与 SHA256。
- [ ] 发布说明写明最低系统要求、已知限制、实际构建的平台。
- [ ] 发布说明注明哪些环节已实测、哪些未验证，不把"未验证"写成"已跑通"。
- [ ] 若启用了自动更新且签名密钥与旧版本不同：必须提醒 **1.0.0 ~ 1.0.3 用户
      手动下载安装包**，这些客户端内置旧公钥，对新钥签的清单验签会失败。
