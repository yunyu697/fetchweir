# 安装范围与权限

本文记录两种安装范围的行为差异、提权开关的真实实现方式，以及本机实测到哪一步。
所有路径均按当前构建（`1.0.0-alpha2`，x86_64 Windows）实机核对过；未做的项单独标注。

## Windows：两种安装范围

| 项目 | 仅当前用户（默认） | 所有用户 |
| --- | --- | --- |
| 是否需要 UAC | 否 | 是，安装与卸载都会弹权限请求 |
| 安装目录 | `%LOCALAPPDATA%\Fetchweir` | `%ProgramFiles%\Fetchweir` |
| 开始菜单 | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Fetchweir.lnk` | 所有用户开始菜单 |
| 桌面快捷方式 | `%USERPROFILE%\Desktop\Fetchweir.lnk` | 公共桌面 |
| 卸载项 | `HKCU\...\Uninstall\Fetchweir` | `HKLM\...\Uninstall\Fetchweir` |
| 自启动归属 | 当前用户 `HKCU\...\Run` 或当前用户计划任务 | 仍然是当前用户（自启动是登录行为，不跟随安装范围） |
| 数据目录 | `%APPDATA%\Fetchweir` | 每个用户各自的 `%APPDATA%\Fetchweir` |
| 其他用户可见性 | 不可见 | 程序所有人可见，但设置/记录仍各自独立 |

默认建议：**仅当前用户**。理由：不需要管理员口令，升级与卸载不会被 UAC 打断；
数据在漫游目录，多个 Windows 账户各自独立，不会互相覆盖。共享电脑、需要给所有账户预装时才选「所有用户」。

实机核对（仅当前用户，`/S` 静默安装，未占前台）：

| 检查项 | 结果 |
| --- | --- |
| 安装退出码 | `0` |
| 安装目录内容 | `fetchweir.exe`、`yt-dlp.exe`（sidecar）、`WebView2Loader.dll`、`uninstall.exe` |
| 开始菜单快捷方式 | 存在 |
| 桌面快捷方式 | 存在 |
| 卸载项 | `HKCU\...\Uninstall\Fetchweir`，DisplayVersion = `1.0.0-alpha2`，InstallLocation 指向安装目录 |
| 安装后识别 | `install_info` 返回 `scope = perUser`、`installDir = %LOCALAPPDATA%\Fetchweir`、`dataDir = %APPDATA%\Fetchweir` |
| 卸载后 | 程序文件与快捷方式删除、卸载项删除；`%APPDATA%\Fetchweir` 中的设置与记录保留 |

数据目录与安装目录分离的原因：Windows 用户级安装的默认目录就是 `%LOCALAPPDATA%\Fetchweir`，
如果数据也放这里，卸载会把用户设置一起删掉。因此数据改到 `%APPDATA%\Fetchweir`；
早于该改动的本地调试数据会留在旧目录，属于开发残留，不随安装包分发。

「所有用户」安装包由发布流程额外产出（`*-setup-allusers.exe`），已在本机实机安装并卸载：

| 项目 | 结果 |
| --- | --- |
| 安装（`/S`，UAC 放行） | 退出码 0 |
| 程序目录 | `C:\Program Files\Fetchweir`：`fetchweir.exe`、`yt-dlp.exe`、`WebView2Loader.dll`、`uninstall.exe` |
| 开始菜单 | `%ProgramData%\Microsoft\Windows\Start Menu\Programs\Fetchweir.lnk` |
| 桌面快捷方式 | `C:\Users\Public\Desktop\Fetchweir.lnk` |
| 卸载项 | `HKLM\...\Uninstall\Fetchweir`，DisplayVersion = `1.0.0-alpha2` |
| 安装后识别 | `install_info` 返回 `scope = perMachine`、`scopeLabel = 所有用户（Program Files）` |
| 数据目录 | 仍为当前用户的 `%APPDATA%\Fetchweir`（多用户各自隔离） |
| 卸载后 | Program Files 目录、公共开始菜单与桌面快捷方式、HKLM 卸载项全部清空；`%APPDATA%\Fetchweir` 保留 |

所有用户安装会改写公共位置并注册 HKLM 卸载项，因此安装器需要管理员权限（UAC）。

## macOS

| 项目 | 用户目录 | `/Applications` |
| --- | --- | --- |
| 位置 | `~/Applications/Fetchweir.app` | `/Applications/Fetchweir.app` |
| 权限 | 不需要管理员 | 需要管理员（Finder 会提示输入） |
| Gatekeeper | 未公证的包首次打开会被拦，需要「右键 → 打开」或移除隔离属性 | 同上；放到 `/Applications` 不会自动放行 |
| 数据 | `~/Library/Application Support/Fetchweir`，与安装位置无关 | 每个用户各自一份 |
| 多用户 | 仅当前用户可见 | 所有用户可见，数据仍各自独立 |

发布前需要 Developer ID 签名 + 公证（notarytool），否则 Gatekeeper 会拦截；
这一步依赖证书与 Apple 账号，本仓库的 CI 目前只做未签名构建。

## Linux

| 项目 | 用户级 | 系统级 |
| --- | --- | --- |
| 位置 | AppImage 或 `~/.local/...` | `/usr/lib/fetchweir`、`/usr/bin` 或 `/opt/fetchweir` |
| 权限 | 普通用户 | 需要 root（`sudo`） |
| 数据 | `~/.local/share/Fetchweir`（XDG_DATA_HOME） | 每个用户各自一份 |
| 卸载 | 删除 AppImage / 删除用户目录 | 包管理器或 root 删除 |

**Flatpak 与系统级互斥**，且 Flatpak 沙箱内无法把 Native Messaging 宿主注册到宿主系统的浏览器配置：
沙箱版只能用手动下载与剪贴板粘贴链接，扩展嗅探不可用。需要扩展嗅探时请用 AppImage / deb 版本。
发行版差异（依赖库、托盘支持、`libwebkit2gtk` 版本）未逐一验证。

## 「始终以管理员身份运行」（仅 Windows）

实现方式：

1. 启动时读取设置；若开启且当前进程未提权，用 `ShellExecuteW("runas")` 以 `--elevated-launch` 重新拉起自身，
   当前进程退出。用户在 UAC 选「否」时保持普通权限继续运行，不阻塞启动。
2. 真实提权状态用进程令牌判断（`OpenProcessToken` + `GetTokenInformation(TokenElevation)`），不看窗口标题。
3. 自启动不能只靠 `HKCU\...\Run`（该方式启动的是普通权限进程）。开启管理员运行且开启自启动时，
   改注册计划任务 `FetchweirElevated`：`schtasks /SC ONLOGON /RL HIGHEST`，登录即最高权限启动；
   同时删除 Run 项，避免两条自启路径互相覆盖。关闭管理员运行或关闭自启动时删除该计划任务并恢复/清理 Run 项。
4. 设置页展示当前安装范围、维护方式（切换范围需卸载重装）、提权状态与自启动注册情况。

UIPI 副作用：提权窗口的完整性级别高于普通资源管理器，Windows 会拦截从非提权程序拖入的文件/链接。
界面在提权状态下显示提示条，建议改用「粘贴链接」或浏览器扩展下发下载（扩展经 Native Messaging 走本地回环，
不受窗口完整性级别影响）。本产品的原生拖放导入尚未实现，因此当前没有实际被拦的功能，提示按平台限制预先说明。

已实测（UAC 已放行，逐项记录）：

| 项目 | 结果 |
| --- | --- |
| 普通权限令牌判断 | `elevated = false`，完整性级别 `S-1-16-8192`（Medium） |
| 自启动开启 | `HKCU\...\Run\Fetchweir` 写入安装后的 exe 路径；`runRegistered = true` |
| 自启动关闭 | Run 值删除；`runRegistered = false` |
| 计划任务（未开管理员运行） | 不创建 `FetchweirElevated`（`taskRegistered = false`） |
| 开启「始终以管理员身份运行」后启动 | 新进程令牌 `TokenIsElevated = true`，完整性级别 `S-1-16-12288`（High）；判断依据是令牌，不是窗口标题 |
| 计划任务内容 | `schtasks /Query /XML`：`<LogonTrigger>` 存在、`<RunLevel>HighestAvailable</RunLevel>`、`<Command>` 指向当前 exe |
| 计划任务实际启动 | 无其它实例时 `schtasks /Run` 拉起的进程同样 `elevated = true`、`S-1-16-12288`，证明任务动作是提权启动；`schtasks /End` 可终止 |
| 提权下的 Native Messaging | 数据目录写入新的 `nm-endpoint.json`，`pid` 与提权进程一致，本地回环与宿主 IPC 正常 |
| 提权下的托盘 | 应用常驻时从任务栏实拍：`docs/ui-shots/tray-live-notification-area.png`、`tray-live-overflow.png` |
| 提权下的单实例 | 普通权限启动第二个实例：退出码 0、进程数仍为 1，提权首实例收到转发参数（`single-instance-probe.json` 记录 argv） |
| 关闭后恢复 | 设置改回 `runAsAdmin = false` 后启动：`elevated = false`、`S-1-16-8192`；`FetchweirElevated` 已删除，`HKCU\...\Run` 无 `Fetchweir` 值 |

单实例实现：`tauri-plugin-single-instance`（命名互斥量 `dev.fetchweir.app-sim` + `WM_COPYDATA` 转发）。
提权实例的接收窗口默认被 UIPI 拦截低完整性进程发来的 `WM_COPYDATA`，第二个实例只能自行退出、唤不醒已有窗口；
启动时调用 `ChangeWindowMessageFilterEx` 只放行 `WM_COPYDATA` 这一条消息，其余消息仍受 UIPI 约束。

未实测（如实保留）：

- 真实注销 → 重新登录触发 `ONLOGON`：本次只核对了触发器存在与任务动作的提权结果，未做实际注销登录。
- 从资源管理器向提权窗口拖入文件被 UIPI 拦截的实际表现：原生拖放导入本就未接通，没有可测功能。
- 本次关闭管理员运行是用设置文件 + 提权删除计划任务完成的，没有点击界面开关；开关处理函数 `set_run_as_admin(false)`
  的撤任务分支只做了代码走查，未通过界面复测。

## 未验证项与限制（如实）

- 多用户同时登录：未验证两个账户同时运行时的自启动、托盘与数据隔离；设计上数据在各自 `%APPDATA%`。
- Linux 各发行版的依赖差异、Flatpak 沙箱下的托盘与扩展能力：未验证。
- 卸载不清理 Native Messaging 注册表项与漫游目录中的宿主清单；下次启动会幂等重写，残留键指向已删除的 exe 时会启动失败但不影响应用本体。
- 单实例已实现并在普通权限、提权两种状态下各验证一次（见上表）；仍需注意：不同用户会话之间不共享互斥量，不做跨用户单实例。
- macOS 公证、Linux 系统级安装需要签名证书 / root 权限，本机与当前会话都不具备，未执行。
