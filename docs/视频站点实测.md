# 视频站点实测（2026-11-08）

这一页记录的是**真实站点、真实下载、ffprobe 核对**的结果，不是界面演示。
所有结论都能用下面「复现方式」里的命令重跑；原始数据在 `docs/evidence/video-*.json`。

## 环境

| 项 | 值 |
| --- | --- |
| 应用 | 本机 release 构建（`D:\fw-build\fetchweir\release\fetchweir.exe`），离屏 `FW_SMOKE=1` 驱动 |
| 解析器 | `yt-dlp 2026.10.26`（随包 sidecar） |
| 合并工具 | `ffmpeg 9.0.2-essentials_build-www.gyan.dev`（105,423,872 字节，随包 sidecar） |
| 校验 | `ffprobe -v error -print_format json -show_format -show_streams` |
| 网络 | 本机家宽/办公网（非数据中心代理） |

驱动方式：WebView2 远程调试 → 界面里填 URL、按 Enter 解析、点选格式行、点击「加入下载」，
下载完成后在磁盘上找到成品并用 ffprobe 读实际编码参数。全程不读后端内部字段当结论。

## 站点结论

| 站点 | 能不能用 | 说明 |
| --- | --- | --- |
| Bilibili（`BV1GJ411x7h7`） | **可用** | 15 档：12 档纯视频（H.264/HEVC/AV1 × 1080p/720p/480p/360p）+ 3 档纯音频。纯视频流由 ffmpeg 自动合并最佳音轨 |
| archive.org（`BigBuckBunny_124`） | **可用** | 3 档直链整文件（mp4 / ogv / avi），走自家分段引擎，不经 yt-dlp 下载 |
| YouTube（`YE7VzlLtp-4`） | **不可用** | 解析阶段被 bot 校验挡住：`Sign in to confirm you're not a bot`。需要登录态 Cookie / PO token，本机没有可用账号，未做绕过 |
| Vimeo（`1084537`） | **不可用** | 解析阶段 `HTTP 403`（站点对数据中心/VPN 出口的限制）。换住宅网络可能可用，本机无法验证 |

DRM 内容没有试：产品边界是不碰 DRM，解析器标记 `has_drm` 的格式整行禁用、后端硬拒绝。

## 用例 1：Bilibili 1080p 纯视频流 + 自动合并音轨

| 步骤 | 结果 |
| --- | --- |
| 解析 | 12 档视频行 + 3 档音频行；标题、时长（212.39s）与解析器一致，用时 2.7s |
| 选档 | `30080` = 1920×1080 H.264 25fps 2629 kbps 66.6 MB，界面标注「需合并音轨」 |
| 界面汇总 | 音频列「自动配 AAC 5.2 MB」，估算总体积 **71.7 MB**（含音轨，不再只算视频） |
| 下载 | 委派解析器 `-f 30080+bestaudio/best` + ffmpeg 合并，7.7s 完成 |
| 落盘 | `【官方 MV】Never Gonna Give You Up - Rick Astley.mp4`，**75,234,071 字节（71.75 MiB）** |
| ffprobe 视频 | `h264` High、`avc1.640032`、1920×1080、25 fps、2,627,607 bps |
| ffprobe 音频 | `aac` LC、48 kHz、双声道、201,984 bps（= 解析器 bestaudio 档 203.79 kbps） |

体积对得上：66.6 MB（视频 69,809,437 字节）+ 5.2 MB（音频 5,410,339 字节）≈ 75.2 MB。

## 用例 3：archive.org 直链整文件

| 步骤 | 结果 |
| --- | --- |
| 解析 | 3 档，全部为整文件（mp4 640×360 / ogv 533×300 / avi 1280×720），解析器不给编码字段 |
| 选档 | `1` = MP4 640×360 59.0 MB；界面显示「站点未标注编码」「含于所选文件」 |
| 下载 | 走自家分段引擎（`mode: direct`），9.6s |
| 落盘 | `big_buck_bunny_720p_surround.mp4`，**61,878,609 字节（59.0 MiB）** |
| ffprobe | `h264` Constrained Baseline 640×360 24 fps 697 kbps + `aac` 44.1 kHz 双声道 128 kbps |

站点文件名含 `720p` 但内容实际是 640×360，界面显示以解析器返回的分辨率为准（与 ffprobe 一致）。

## 格式真实性核对

方法：把界面的数据源（后端 `probe_video` 返回的每个格式）与 `yt-dlp -J` 原始矩阵**逐档逐字段**比对，
字段包括宽度、高度、容器、视频编码、音频编码、码率、体积、帧率、协议、是否需要合并音轨。

| 站点 | 解析器档数 | 界面档数 | 不一致 |
| --- | --- | --- | --- |
| Bilibili | 15 | 12（视频页）+ 3（音频页）= 15 | 0 |
| archive.org | 3 | 3 | 0 |

体积来源是 `max(filesize, filesize_approx)`，与解析器给的值一致（界面四舍五入到 0.1 MB）。

关于「显示可选但实际下不了」：本轮**没有发现**。Bilibili 15 档全部可点选、无置灰；实际下载验证了
1080p H.264 纯视频流、46 kbps 纯音频两条不同代码路径，archive.org 验证了直链整文件路径。
其余 12 档（HEVC/AV1 各分辨率、其余音频档）没有逐档下载，但它们与已验证的档位走完全相同的两条路径
（纯视频流 → 解析器 + ffmpeg 合并；纯音频 → 解析器直下），不存在单独的下载分支。

## 本轮发现并修复的问题

1. **核心卖点在主站不可用**：Bilibili 只提供分离流，旧逻辑把「纯视频流」整行禁用，后端直接报
   「v1 未随包 ffmpeg」。现在区分「纯视频」（走 `{id}+bestaudio/best` + ffmpeg 合并）与「纯音频」
   （解析器直下），ffmpeg 作为 sidecar 随包。
2. **成品路径丢失**：中文标题在 Windows 上按本地代码页输出，后端按 UTF-8 读行失败，`done.path` 为 null。
   改为按字节读行 + `--encoding utf-8`，并用 `FETCHWEIR:` 前缀标记成品路径。
3. **8.3 短路径**：含非 ASCII 文件名时解析器打印 `C:\Users\TYLERZ~1\...`。后端 `canonicalize` 还原长路径，
   保存目录同样处理。
4. **编码未标注的整文件被归成音频**：archive.org 这类格式 `vcodec/acodec` 为空但有明确分辨率，
   会被渲染到「音频」页且无推荐档。现在按「整文件」处理，归视频页、可作为推荐档、体积按整文件算。
5. **估算总体积漏算音轨**：选 1080p 纯视频流时界面显示 66.6 MB，实际成品 71.75 MiB。
   现在音频列给出实际音轨体积，总计按「视频 + 最佳音轨」合计。
6. **界面文案过时**：设置页「转封装工具 · 未随包」、视频页「v1 不随包 ffmpeg」全部与事实相反。
   现在设置页由新命令 `video_tools` 返回的真实路径显示「就绪 / 缺 ffmpeg / 缺 yt-dlp」，
   视频页说明改成当前行为。
7. **测试脚本自己踩的坑**：第一版脚本点的是侧栏「视频」分类（`navVideo`），不是「视频解析」工具页
   （`navVideoTool`），读到的格式行其实在隐藏 DOM 里——数据是真的，但截图和「界面可见」不成立。
   现在脚本会断言 `viewVideo` 可见、URL 输入框可交互后才继续，三个用例全部重跑。

## 没做到的

- Bilibili 1080p+（大会员）、4K/HDR、杜比音频等需要登录/付费的档位未验证，也没有登录态 Cookie 注入界面。
- YouTube / Vimeo 的阻断是站点侧策略与网络出口问题，本轮没有做 Cookie 导入或代理。
- 没有逐档下载全部 15 档（见上文说明）。
- 站点改版、签名 URL 过期、地区限制都会让结果变化；这里的结论只对应 2026-11-08 这一次运行。

## 复现方式

```powershell
# 需要先构建 release，并把 yt-dlp / ffmpeg 放到 exe 同级（tauri externalBin 会自动带过去）
node tools/Test-FwVideoSite.mjs '<exe 路径>' 'https://www.bilibili.com/video/BV1GJ411x7h7' 30080 bili
node tools/Test-FwVideoSite.mjs '<exe 路径>' 'https://www.bilibili.com/video/BV1GJ411x7h7' 30216 bili-audio
node tools/Test-FwVideoSite.mjs '<exe 路径>' 'https://archive.org/details/BigBuckBunny_124' 1 ia
```

脚本会：离屏启动应用 → 解析 → 选档 → 加入下载 → 等成品落盘 → ffprobe → 与 `yt-dlp -J` 逐档比对，
输出 `docs/evidence/video-<label>.json` 和 `docs/ui-shots/video-<label>-*.png`。
